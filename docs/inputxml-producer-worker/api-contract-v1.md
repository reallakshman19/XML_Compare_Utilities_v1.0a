# InputXmlProducerService.v1

## Purpose

Expose existing raw InputXML categorization through a producer-traceable, transport-neutral service and the browser-worker operation:

```text
producer.categorizeInputXml
```

## Request

```json
{
  "schema": "InputXmlProducerCategorizeRequest.v1",
  "requestId": "optional-request-id",
  "producer": {
    "id": "xml-builder",
    "repository": "reallaksh19/3D_Converters",
    "module": "tabs/xml-builder-tab.js",
    "operation": "buildXmlCiiCustomInputXml",
    "version": "optional-version",
    "artifactRole": "generated-inputxml"
  },
  "source": {
    "filename": "model.input.xml",
    "content": "<CAESARII XML_TYPE=\"Input\">...</CAESARII>"
  }
}
```

`producer.id`, `source.filename`, and `source.content` are the adoption boundary. The service calculates fingerprints itself.

## Success result

```text
InputXmlProducerCategorizeResult.v1
success = true
producer trace
source filename and fingerprint
input PIPINGELEMENT count
categorized summary
categorized service validation
categorized-review-document artifact
```

The artifact is generated by `inputXmlToCategorizedInputXml()` and must pass `CategorizedInputXmlService.v1` validation with `require-v3` policy.

## Engineering failure result

Malformed or unsupported InputXML returns:

```text
InputXmlProducerCategorizeResult.v1
success = false
artifact = null
structured diagnostics
```

Important diagnostic codes:

```text
PRODUCER_ID_MISSING
INPUTXML_EMPTY
INPUTXML_ROOT_INVALID
INPUTXML_TYPE_INVALID
PIPINGMODEL_MISSING
PIPINGELEMENT_MISSING
CATEGORIZATION_FAILED
CATEGORIZED_OUTPUT_INVALID
```

These are service results, not worker protocol failures.

## Authority

```text
producer module                    = InputXML generation authority
CategorizedInputXmlConverter.js    = categorization authority
CategorizedInputXmlService.v1      = categorized validation authority
browser worker                     = transport authority
```

## Exclusions

- no repair or enrichment;
- no normalized reconciliation;
- no InputXML mutation;
- no CII conversion;
- no UI or producer-module adoption;
- no cross-repository distribution in this Work Pack.
