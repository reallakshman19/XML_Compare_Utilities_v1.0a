## Defect reproduced by Owner

Direct browser selection of `R2.xlsx` and `R3.xlsx` exposed raw OOXML/ZIP bytes beginning with `PK... [Content_Types].xml` in the revision text areas. The UI was calling `File.text()` for every selected file, so XLSX packages were incorrectly passed to the flat-table parser. Resulting schema diagnostics reported nonsense one/two-column tables and missing governed Support Report columns.

## Hotfix boundary

The hotfix changes only browser file ingress:

- `.xlsx` is accepted by the revision file picker;
- XLSX uses `File.arrayBuffer()` and SheetJS workbook parsing, never `File.text()`;
- Support Report worksheet discovery uses the same benchmark rule: exact `PIPE` plus Civil Secondary Support semantics within the first 40 worksheet rows;
- formula cells are emitted as formula text prefixed with `=` to preserve primary-support reference identity;
- the extracted worksheet table is serialized to ordinary CSV text and then handed to the existing governed Table-to-Categorized-XML parser;
- CSV/TSV/TXT/paste behavior is unchanged;
- missing Support Report headers fail explicitly at ingress.

No lineage, candidate, XML graph, typed-event, remark, four-bucket benchmark, or output authority was changed.
