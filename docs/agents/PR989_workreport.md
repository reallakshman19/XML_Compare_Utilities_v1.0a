## 1. Mission

Make the CII Workspace authority flow explicit:

```text
independent landmark evidence
  -> paired Base Anchor suggestions
  -> engineer Accept
  -> locked anchor used for correspondence
  -> correspondence Decision
  -> Engineering Delta Approval projection
  -> reviewed/locked-only Transfer Preview
```

The old SOURCE/TARGET `Suggested landmarks` lists were not paired suggestions. They remain available only as `Landmark evidence (unpaired)`.

## 2. Base Anchor suggestions

New `CIIWorkspaceBaseAnchorSuggestion.v1` is generated by `cii-workspace-anchor-suggestions.js`.

Pairing is topology-only and explicitly excludes:

```text
NODE_NUMBER_OFFSET_NOT_USED
OD_NOT_USED
WALL_NOT_USED
```

The candidate pool itself is dimension-free; it is formed only from structural cues:

- branch degree;
- rigid adjacency;
- terminal status;
- bend adjacency;
- node-name presence.

Pair evidence uses:

- exact node degree compatibility;
- incident structural component-kind similarity;
- neighbour-degree multiset similarity;
- dimension-free 1/2/3-hop topology-neighbourhood similarity;
- robust structural-reason similarity.

Suggestions require mutual-best SOURCE/TARGET pairing. Default gates:

```text
minimum pair score = 65
winner gap          = 8
HIGH                = score >= 90 and gap >= 12
MEDIUM              = score >= 78 and gap >= 8
otherwise           = REVIEW
```

Every suggestion remains:

```text
status = SUGGESTED
authority = EVIDENCE_ONLY_ENGINEER_ACCEPT_REQUIRED
reviewRequired = true
```

No suggestion creates a locked anchor automatically.

## 3. Tab 1 UI

The inspection UI now presents:

```text
Base Anchor suggestions
SOURCE ↔ TARGET | Basis | Confidence | Review | Action
```

Each row exposes `Accept base anchor`. Accept fills the reviewed SOURCE/TARGET anchor fields; the engineer must still run `Compare models` before core normalization turns the pair into `USER_LOCKED` anchor authority.

Independent lists are relabelled `Landmark evidence (unpaired)` and retain visible `SUGGESTED` evidence for compatibility.

## 4. Correspondence Review bulk acceptance

Added a dedicated `Bulk Accept` frame:

```text
Accept all HIGH
Accept all MEDIUM
```

Bulk acceptance requires:

- requested confidence band;
- `identityBound === true`;
- row not already LOCKED.

The UI explicitly states that REVIEW and UNRESOLVED are never bulk accepted. Existing per-row LOCK / ACCEPT / REJECT controls remain.

Bulk actions stage explicit `ACCEPT` decisions only; they do not bypass the review ledger.

## 5. Engineering Delta Approval

The Engineering Delta Grid now has an `Approval` column.

Approval is not a new delta authority. It is a read-only projection of the parent correspondence Decision:

```text
ACCEPTED -> APPROVED
LOCKED   -> LOCKED
REJECTED -> REJECTED
no decision -> PENDING
```

Pending UI decisions are visible immediately. They become authoritative for Transfer Preview only when the user clicks `Apply approvals to Transfer Preview`, which uses the existing `updateCiiReviewDecisions()` review-ledger contract and rebuilds the preview.

## 6. Transfer Preview

Tab 3 now makes the authority chain explicit.

Banner is always:

```text
TRANSFER PREVIEW · BLOCKED
Preview only. Target mutation is not implemented. Geometry, node numbering, topology, OD and wall remain protected.
```

Preview-plan readiness is shown separately (`PREVIEW_READY` or `BLOCKED`) and cannot be confused with target-mutation authority.

Transfer rows now expose `Approval authority` from the existing operation `matchAuthority.status` (`REVIEWED` or `LOCKED`). The UI states:

```text
Only accepted/locked correspondence can produce transfer rows.
```

Both Apply-to-target controls remain disabled. No target writer/mutator is added.
