SSK-TS-3I qualifies explicit application of one exact support move preview. The accepted result is a branch-local support-adjustment register entry. It is not a source-record edit, construction transaction, construction decision, or package-persistence mutation.

## Authority separation

The implementation preserves four distinct authorities.

### Source and construction authority

The following remain immutable:

- source records and indexed source evidence;
- `SequentialConstructionSession.v1`;
- `ConfirmedSequentialConstruction.v1`;
- construction decision, transaction, undo, redo, and repair ledgers;
- construction command journal;
- workspace package and exported source payloads.

Support adjustment acceptance does not rewrite any of these values.

### Base support projection

`SequentialConfirmedSupportProjection.v1` remains the immutable projection derived from accepted pipe construction and source support evidence.

The base projection is retained as the ancestry root for every adjustment. It is never mutated or replaced in place.

### Support-adjustment register

`SequentialSupportAdjustmentRegister.v1` is an immutable ordered register scoped to one branch and one complete base support projection.

Each `SequentialSupportAdjustmentEntry.v1` binds:

```text
construction fingerprint
support / family / carrier identities
exact from and to positions
independently resolved carrier evidence
target and preview operation identities
actor / reason / evidence
exact applied time
canonical adjustment identity
```

The register has a deterministic head fingerprint. Append requires the new entry's `fromPosition` to equal the current effective support point.

### Effective support projection

The effective support projection is independently regenerated by applying the register to the immutable base projection.

One adjustment updates all supported position representations consistently:

```text
top-level support glyph
branch-bundle support glyph
resolved support-family position
carrier-owned support-family position
```

The effective projection records adjustment authority metadata and audit evidence that the base projection was not mutated.

## Same-carrier application rule

The requested XYZ is independently checked with the existing Sequential support-carrier geometry solver.

Application is permitted only when:

1. the current support, family, carrier, scene, read model, edit authority, and register identity match the preview;
2. the carrier exists in the immutable base support projection;
3. the requested point resolves on that same carrier;
4. the resolved status is an accepted exact carrier location;
5. the solver's canonical point equals the requested point within `1e-9 mm`.

The service rejects:

- off-carrier coordinates;
- cross-carrier reassignment;
- silently projected or snapped points;
- stale support positions;
- stale register heads;
- changed base projections;
- tampered preview targets, intents, drafts, prepared IDs, entries, or effective projections.

## Preview, prepare, review, apply

```text
pick certified support marker
→ enter absolute X/Y/Z
→ actor + reason + evidence
→ Preview move draft
→ validate canonical MOVE_ENTITY draft
→ prepare immutable support-adjustment candidate
→ review support, carrier, from, to, status, authority, and next register
→ Apply adjustment or Cancel
```

Selection and typing alone do not stage or publish anything.

Preview creates:

- one `EngineeringEditIntent.v1` with `MOVE_ENTITY`;
- one `EngineeringSvgDraftSnapshot.v1` geometry entry;
- one non-published support move preview;
- one deterministic prepared support-adjustment candidate.

Preparation does not publish authority.

Apply revalidates the current edit authority, immutable base projection, current register head, canonical register tail, and independently regenerated effective projection before the boundary stores the new register.

Cancel clears the draft and prepared candidate without changing support, construction, source, or journal authority.

## Branch-local boundary

`SequentialSupportAdjustmentBoundary.v1` owns an in-memory register map keyed by branch ID.

The stored record is also bound to the complete base support-projection fingerprint. Therefore:

- switching to another branch exposes that branch's own register;
- switching back restores the prior branch-local adjustment;
- a change to pipe construction clears an incompatible register;
- a support-only source-evidence change also clears the register, even when the confirmed pipe construction fingerprint is unchanged.

The boundary synthesizes:

```text
effective command state
effective owner snapshot
certified read model
certified Draft Edit scene
```

It does not call workspace restore, package persistence, storage APIs, or the construction command service.

## Authority fingerprints

The adjusted support register and complete effective support projection participate in:

- engineering revision identity;
- owner-snapshot identity;
- scoped read authority;
- scene identity;
- support target identity;
- complete edit authority.

Acceptance therefore invalidates the former target, draft, prepared candidate, scene, and read authority.

## UI containment

The support panel exposes three actions only:

```text
Preview move draft
Apply adjustment
Cancel
```

Apply is disabled until an exact preview has produced one prepared candidate.

The review includes:

- prepared ID;
- adjustment ID;
- support and carrier IDs;
- exact from and to coordinates;
- carrier position status;
- expected authority ID;
- resulting register head.

The panel has no direct boundary, gateway, journal, or persistence access. The feature owns the preview/apply service and invokes publication only after the explicit Apply action.

## Construction-command compatibility

The existing twelve supervised construction commands remain on `SequentialWorkspaceCommandBoundary.v1` and `SequentialDraftEditCommandGateway.v1`.

Support selection clears construction targets. Candidate or reversal selection clears support targets and drafts.

The adjustment boundary is used only for support scene/read/target/application authority. It does not replace or extend the construction command gateway.

The browser lifecycle companion remains admitted and unchanged.
