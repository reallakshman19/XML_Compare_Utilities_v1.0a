# Material objective

Implement WP-PSA-003 so Support Report can discover and select exact parent-zone scope and optionally consume Navisworks Clash-within-Supports XML as typed Primary Support Assembly connectivity before the existing assembly-count projection.

# Product changes

## `support-report-zone-scope.js`

Introduces `SupportReportZoneScope.v1` and pure helpers to:
- discover exact ancestor zone nodes independently from the primary/piping side and secondary/support side;
- normalize selected zone IDs by exact path-node identity;
- scope primary Support Report evidence rows;
- scope optional support-member relationship rows;
- emit an auditable scope summary.

Compatibility:
- raw parser rows (`primaryPath` / `secondaryPath`) are supported;
- grouped audit rows (`primaryPaths` / `secondaryPaths`) are also supported;
- empty selection on either side means no restriction for that side;
- when both sides have selections, report-row filtering is conjunctive;
- matching is exact normalized node identity, not substring matching.

## `support-primary-input.js`

Introduces `SupportPrimaryInput.v1`:
1. parse optional Clash-within-Supports XML through shared `parseSupportMemberRelationshipXml()`;
2. apply exact zone scope before authority is built;
3. build `SupportPrimaryRelationshipBundle.v1` only from scoped support-member edges;
4. expose parsed/scoped/excluded row counts and parser diagnostics.

## `support-primary-relationship.js`

Retains the selected zone scope in bundle audit metadata. Connected-component/topology semantics are unchanged.

## `support-report-addon.js`

Adds end-to-end UI plumbing:
- optional **Primary Support Relationship XML** source card;
- exact-zone discovery from the current primary Support Report XML;
- two searchable multi-select columns:
  - Primary / piping-support zones;
  - Secondary / support zones;
- explicit clear/no-restriction behavior;
- zone-scope invalidation of stale report state;
- scoped regrouping of primary Support Report rows before report build;
- scoped relationship XML -> `primaryRelationshipBundle` -> existing Support Report count seam;
- report/debug audit snapshot containing zone scope/catalog and relationship input parsed/scoped counts;
- ready-state visibility for active scope and relationship-vs-geometry fallback mode.

The current-area zone scope deliberately does not filter the typical-reference XML in this leg.

## Cache routing

`support-steel-relationship-bootstrap.js` now version-busts the Support Report addon with `20260915-support-primary-zone-ui-1`, and the addon imports the current bore-axis location chain plus the new zone/input modules.
