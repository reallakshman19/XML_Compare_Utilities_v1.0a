# Material objective

Implement WP-PSA-006 count migration so `TOTAL SUPPORT POINTS ON SECONDARY` is projected through the canonical Primary Support Assembly topology/reconciliation seam while preserving existing geometry count behavior when optional explicit relationship evidence is unavailable.

# Product changes

## `support-primary-counting.js`

Introduces `SupportPrimaryCountProjection.v1`.

Family policy:
- no valid explicit relationship family => exact legacy geometry-group count;
- valid explicit family => all countable explicit assembly IDs contribute, including explicit assemblies not observed by current location groups;
- each `GEOMETRY_ONLY` group contributes one fallback occurrence;
- multiple geometry groups resolving to the same explicit assembly contribute once through the explicit assembly set;
- DATUM/reference-only evidence contributes zero;
- `PARTIAL_EXPLICIT` / `CONFLICT` state activates `EXPLICIT_ASSEMBLY_PLUS_GEOMETRY_AMBIGUITY_FLOOR`, preventing the new count from falling below legacy geometry evidence;
- unsupported relationship schema has no authority.

Each counted group now retains:
- `primarySupportAssemblyId`;
- `primarySupportAssemblyStatus`;
- `primarySupportAssemblyBasis`;
- candidate/provisional IDs;
- family explicit assembly IDs;
- geometry-only group IDs;
- ambiguity count;
- count basis;
- `multiplePrimarySupport`.

## `support-report-engine.js`

Adds optional typed input `primaryRelationshipBundle` and applies the count projection before field/row projection.

Top-level report evidence now exposes:
- `primaryRelationshipBundleSchema`;
- `primarySupportCountSchema`;
- `primarySupportEvidenceMode`;
- `primarySupportFamilySummaries`;
- explicit-authority family count;
- ambiguity family count.

Row evidence exposes the assembly ID/status/basis/candidate/provisional/count-basis and family assembly evidence.

Existing staged Support/Steel `relationshipBundle` remains a separate input and retains its existing carrier/member enrichment authority.

## `support-report-row-enrichment.js`

- `Multiple primary support` is now triggered by `group.multiplePrimarySupport`, i.e. final family assembly count > 1.
- legacy `multipleLocationsOnPipe` remains independently retained in row evidence.
- JSON Trace gains primary-support assembly ID/status/basis/candidates/provisional ID/count basis/family explicit IDs/fallback group IDs/ambiguity count.
