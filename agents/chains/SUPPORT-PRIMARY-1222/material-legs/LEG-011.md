## Release-readiness defect found

The original bore-axis occurrence grouper intentionally treats different known `branchNode` / traversal identities as separate so pipe-return/revisit cases such as PS-12877 do not collapse merely because they occupy nearby coordinates.

The new second-pass orphan resolver could, however, produce `ORPHAN_RECOVERED_GEOMETRY` across **different known traversals** when:
- family matched;
- PIPE matched;
- Bore matched;
- a trusted pipe-wide >=3-point axis existed;
- geometry passed the orphan window;
- the provisional pair was reciprocally unique.

That allowed geometry-only evidence to weaken the prior traversal authority and was therefore a release-readiness defect.

## Fix

Count authority now applies `enforceOrphanTraversalSafety()` after raw orphan evaluation.

If a recovery is:
```text
ORPHAN_RECOVERED_GEOMETRY
+ DIFFERENT_TRAVERSAL
```
then count authority converts it to:
```text
ORPHAN_UNRESOLVED
DIFFERENT_TRAVERSAL_GEOMETRY_RECOVERY_WITHHELD
```
with the original/provisional assembly identity restored.

Explicit-assembly recovery is intentionally **not** blocked: explicit support-member topology remains the only evidence allowed to override traversal separation.

New diagnostic:
`ORPHAN_CROSS_TRAVERSAL_GEOMETRY_WITHHELD`

New summary:
`orphanCrossTraversalGeometryWithheldCount`

Files materially changed for this fix:
- `tabs/support-steel-relationship-builder/support-primary-counting.js`;
- `tabs/support-steel-relationship-builder/support-report-engine.js` (nested count cache token + summary only);
- `tests/support-primary-orphan-safety.test.mjs`.
