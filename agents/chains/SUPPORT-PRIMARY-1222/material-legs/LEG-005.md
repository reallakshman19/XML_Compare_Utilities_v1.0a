# Product changes

## `support-primary-orphan-recovery.js`

Introduces `SupportPrimaryOrphanRecovery.v1` / `SUPPORT_PRIMARY_ORPHAN_V1`.

Ordering:

```text
normal bore-axis grouping
  -> explicit relationship reconciliation
  -> orphan recovery
  -> final family count projection
```

Authority and safety:
- only `GEOMETRY_ONLY` assignments are recovery sources;
- `EXPLICIT_ASSEMBLY`, `PARTIAL_EXPLICIT`, `CONFLICT` and `SYMBOLIC_ONLY` assignments are immutable to this pass;
- targets may be explicit assemblies or provisional geometry groups;
- distinct explicit assembly IDs are never joined;
- multiple qualifying target identities produce `ORPHAN_AMBIGUOUS` and no merge;
- provisional-to-provisional recovery requires reciprocal unique targeting;
- missing evidence for an enabled Family/PIPE/Bore gate fails closed;
- differing branch/traversal nodes may be overridden only when all three Family/PIPE/Bore gates are enabled and pass;
- branch-override pipe-axis evidence requires at least three independent pipe points, so the orphan/target pair cannot define its own override axis.

Geometry uses the existing Support Report bore/axis authority:

```text
axialMm   = |D dot T|
lateralMm = |D - (D dot T)T|
base axial   = 4 * Bore
base lateral = 0.5 * Bore + 25 mm
recovery axial   = base axial * configured axial multiplier
recovery lateral = base lateral * configured lateral multiplier
```

Recovery statuses include:
- `ORPHAN_RECOVERED_EXPLICIT`;
- `ORPHAN_RECOVERED_GEOMETRY`;
- `ORPHAN_AMBIGUOUS`;
- `ORPHAN_NONRECIPROCAL`;
- `ORPHAN_UNRESOLVED`;
- `DISABLED`;
- `NOT_APPLICABLE`.

Audit retains targets/candidates, family/pipe/bore compatibility, branch relationship, axis basis/confidence, measured axial/lateral residuals, base thresholds and recovery thresholds.

## `support-primary-counting.js`

Orphan recovery is inserted between reconciliation and final count projection.

- geometry groups recovered to one explicit assembly add no separate geometry occurrence;
- reciprocal recovered provisional pairs share one deterministic recovered occurrence ID;
- unrelated/non-recoverable legacy groups remain independently countable;
- disabling recovery preserves the pre-LEG-005 geometry count;
- PARTIAL/CONFLICT ambiguity flooring remains unchanged and conservative;
- family summaries and projected groups carry recovery schema/config/resolution evidence.

## `support-primary-orphan-ui-addon.js`

Adds a Support Report `Conservative orphan recovery` configuration card with:
- enable/disable;
- axial multiplier;
- lateral multiplier;
- Same PS/SL Family;
- Same PIPE;
- Same Bore;
- fixed `Require unique target: Always on` policy;
- guarded branch-override help text.

Changing the controls invalidates the displayed report/exports. Controls are disabled while the Support Report build button is busy.

## `support-report-engine.js`

The engine now accepts an explicit `orphanRecoveryConfig` input in addition to UI runtime configuration, and exposes:
- orphan recovery schema/profile/config/summary at report level;
- recovered/ambiguous/unresolved group totals in `report.summary`;
- per-row recovery status, basis, target/candidate IDs, measured axial/lateral values, base/recovery thresholds, axis basis/confidence and branch relationship in row evidence/debug JSON.

## Browser routing

`support-steel-relationship-bootstrap.js` loads the orphan UI addon and advances the top-level Support Report URL with an orphan token. Nested Support Report engine/count imports still use older query tokens; a fresh load is correct, but hot-session cache hardening remains a release follow-up.
