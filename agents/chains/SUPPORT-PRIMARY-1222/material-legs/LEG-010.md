## Material delivered

### Column 22 publication authority

Added `SupportReportTypicalityPublication.v1` and made publication explicit per projected report row.

Deterministic policy:
- final `TYPICAL` + one retained structural candidate -> `PUBLISHED` in Column 22;
- final `REVIEW` -> `WITHHELD` even when `rightFamilyId` is retained for engineering review;
- final `AMBIGUOUS` -> `WITHHELD`;
- final `NO_MATCH` -> `WITHHELD`;
- absent/non-typical result -> `WITHHELD`;
- relationship-only or axis-only candidate cannot populate Column 22 because secondary matchers do not promote a structural rejection/ambiguity.

Publication reason codes:
- `TYPICAL_PUBLICATION_FINAL_TYPICAL`;
- `TYPICAL_PUBLICATION_WITHHELD_REVIEW`;
- `TYPICAL_PUBLICATION_WITHHELD_AMBIGUOUS`;
- `TYPICAL_PUBLICATION_WITHHELD_NO_MATCH`;
- `TYPICAL_PUBLICATION_WITHHELD_NOT_TYPICAL`;
- `TYPICAL_PUBLICATION_WITHHELD_NO_RESULT`.

This removes the prior behavior where both `TYPICAL` and `REVIEW` could populate Column 22.

### Row-level independent audit

Added `SupportReportTypicalityRowAudit.v1` on projected rows with independently visible:
- original structural matcher result/candidate/audit IDs;
- arrangement-resolved structural result;
- relationship-topology result, selected candidate, audit ID and failed signals;
- axis-typicality result, selected candidate, audit ID and failed signals;
- final `TypicalityConsensusV1` result/confidence/basis;
- final result/reason/candidate;
- Column 22 publication decision/reason.

Debug JSON remains lossless around the full report bundle, so this row audit is preserved without flattening matcher authority.

### Column 23 human presentation

Existing machine reason codes remain authoritative. Human-facing remarks now explicitly distinguish:
- all structural + relationship + axis channels agreeing;

- structural + relationship agreeing while axis evidence is unavailable;
- structural-only acceptance with both secondary channels unavailable;
- relationship conflict;
- axis conflict;

For review states with a retained candidate, Column 23 names the candidate as **withheld**, so a blank Column 22 cannot be mistaken for missing candidate context.
